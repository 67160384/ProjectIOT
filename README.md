# ใบเสร็จดี — Offline AI Receipt Analyzer

เว็บไซต์อ่านใบเสร็จภาษาไทย/อังกฤษบน Raspberry Pi 4 (RAM 4 GB): อัปโหลด → Tesseract OCR → Qwen2.5 ผ่าน llama.cpp → ผู้ใช้ตรวจแก้ → SQLite → Dashboard รายเดือน

หลังวิเคราะห์ ระบบกรอกชื่อร้านหรือชื่อลูกค้า วันที่ สินค้า/บริการ จำนวน และราคาที่อ่านได้ลงฟอร์มอัตโนมัติ โดยยึดจำนวนเงินในบรรทัด OCR เป็นหลักและใช้ Local AI ช่วยเติมข้อมูลที่ขาด หาก AI ตอบไม่ครบยังใช้ข้อมูล OCR สำรองได้ หมวดหมู่ตั้งใจเว้นไว้ให้ผู้ใช้พิมพ์เอง และทุกช่องต้องตรวจเทียบภาพก่อนยืนยัน

ช่องส่วนลดรับค่าบวก เช่น สินค้ารวม 104 บาท ลด 6 บาท ให้ใส่ `6.00` ระบบคำนวณยอดหลังลดเป็น 98 บาท หมวดหมู่เป็นข้อความอิสระที่ผู้ใช้พิมพ์เอง

**สถานะ:** อ่านผลล่าสุดใน `docs/TEST_RESULTS.md` ก่อนอ้างว่าระบบพร้อม การกรอกด้วยตนเองยังใช้งานได้เมื่อ AI ไม่พร้อม และหน้าจอจะแจ้งสถานะจริง ผลบน cloud ไม่ใช่ผลความเร็วหรือความแม่นยำบน Pi

## เริ่มบน Raspberry Pi

ต้องใช้ Raspberry Pi OS **64-bit**, Python 3.11 ขึ้นไป, microSD มีพื้นที่ว่างแนะนำอย่างน้อย 5 GB, แหล่งจ่ายไฟที่เหมาะสม และควรมีระบบระบายความร้อน อินเทอร์เน็ตใช้เฉพาะตอนติดตั้ง/ดาวน์โหลด

1. คัดลอกโฟลเดอร์โปรเจกต์ลง Pi เช่น `~/ProjectIOT` โดยไม่ใช้ชื่อพาธที่มีช่องว่าง จากนั้น:

   ```bash
   cd ~/ProjectIOT
   uname -m  # ต้องเป็น aarch64
   bash scripts/setup_pi.sh
   ```

   สคริปต์ติดตั้ง OCR สองภาษา, Python dependencies, build llama.cpp ด้วย 2 งานพร้อมกัน และดาวน์โหลดโมเดลประมาณ 491 MB จาก repository ทางการ โดยตรวจ SHA256 ตาม `models/model-manifest.json` ไม่ต้องใช้ API key

2. เปิดสอง terminal ในโฟลเดอร์โปรเจกต์:

   ```bash
   bash scripts/start_llm.sh
   ```

   ```bash
   bash scripts/start_web.sh
   ```

3. ตรวจความพร้อมหลังโมเดลโหลดเสร็จ:

   ```bash
   .venv/bin/python scripts/check_ready.py
   hostname -I
   ```

   `full_pipeline_ready: true` แปลว่า OCR และเซิร์ฟเวอร์โมเดลตอบตรวจสุขภาพแล้ว **ยังต้องวิเคราะห์ใบเสร็จจริง** เพื่อยืนยันผลครบขั้นตอน ใช้เบราว์เซอร์มือถือใน Wi-Fi เดียวกัน เปิด IP ของ Pi ที่พอร์ต 5000

4. อัปโหลดใบเสร็จ ตรวจ/แก้ชื่อร้าน วันที่แบบ ค.ศ. รายการสินค้า ราคาและหมวดหมู่ แล้วกดยืนยันก่อนดู Dashboard

5. เมื่อทดสอบด้วยตนเองผ่านแล้ว หยุดโปรแกรมทั้งสองใน terminal ด้วย Ctrl+C และติดตั้งเปิดอัตโนมัติ:

   ```bash
   bash scripts/install_services.sh
   systemctl status receipt-llm receipt-web
   ```

   สคริปต์ไม่ทับ unit เดิม การดู log ใช้ `journalctl -u receipt-web -u receipt-llm -n 100 --no-pager` หากย้ายโฟลเดอร์ ต้องแก้พาธใน unit ให้ตรงก่อนเริ่มใหม่

## ทดสอบออฟไลน์บน Pi

ตัด WAN/อินเทอร์เน็ตขาออก แต่คง Wi-Fi ภายในให้มือถือเข้าถึง Pi โหลดหน้าเว็บใหม่ อัปโหลดภาพที่ยังไม่เคยใช้ วิเคราะห์ด้วย AI ตรวจแก้ ยืนยัน เปิด Dashboard แล้วรีบูต Pi ตรวจว่าข้อมูลเดิมยังอยู่ บันทึกเวลาและถ่ายคลิปจริงตาม `docs/PI_ACCEPTANCE.md`

Bootstrap, Chart.js และฟอนต์อยู่ใน `static/vendor/` ทั้งหมด แอปไม่เรียก CDN หรือ AI ภายนอก `LLAMA_URL` รับเฉพาะ HTTP loopback และ llama.cpp ฟังที่ 127.0.0.1:8081 เท่านั้น

## พัฒนาบน Linux x86_64

ติดตั้ง Tesseract พร้อม `tha` และ `eng` ด้วย package manager ของเครื่อง แล้ว:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python app.py
```

ตัวแอปโดยตรงฟังเฉพาะ loopback; สคริปต์ `start_web.sh` เปิดฟัง LAN สำหรับ Pi หากยังไม่มีโมเดลสามารถทดสอบ OCR และการกรอกด้วยตนเองได้ แต่ห้ามนับว่า Local AI ผ่านแล้ว การ build llama.cpp บน x86 ใช้ revision ใน `scripts/setup_pi.sh` และตั้ง `-DGGML_NATIVE=OFF` สำหรับ binary ที่ต้องย้ายเครื่อง

## การตั้งค่า

| ตัวแปร | ค่าเริ่มต้น / หน้าที่ |
|---|---|
| `RECEIPT_INSTANCE` | `instance/` ในโปรเจกต์; ฐานข้อมูล รูป และ session key |
| `LLAMA_URL` | `http://127.0.0.1:8081` |
| `APP_HOST` | `127.0.0.1` เมื่อเรียก `app.py`; สคริปต์เปิดเว็บตั้ง `0.0.0.0` |
| `APP_PORT` | `5000` |
| `TESSDATA_PREFIX` | ตั้งเฉพาะเมื่อติดตั้งไฟล์ภาษาในที่อื่น |
| `LLAMA_BIN` / `MODEL_PATH` | override ตำแหน่ง binary / GGUF ใน `start_llm.sh` |
| `RECEIPT_PYTHON` | override Python ใน `start_web.sh` |

รันเว็บ **หนึ่ง process** ด้วย Waitress ตามสคริปต์ เนื่องจากคิววิเคราะห์เป็นเธรดเดียวใน process นั้น ไม่ใช้ Gunicorn หลาย workers หรือ Flask reloader ระบบรับงานค้างได้ไม่เกิน 3 ใบ และกู้รายการที่ถูกตัดกลางทางให้กลับมาตรวจด้วยตนเองเมื่อเริ่มใหม่

## ทดสอบ

```bash
.venv/bin/python -m pytest -q
.venv/bin/python scripts/make_sample_receipt.py
.venv/bin/python scripts/browser_smoke.py
.venv/bin/python scripts/browser_smoke.py --require-ai
.venv/bin/python scripts/model_smoke.py
```

Browser smoke ต้องมี Chromium ที่ `/usr/bin/chromium`, แอปทำงานที่พอร์ต 5000 และ OCR สองภาษา ควรรันกับ `RECEIPT_INSTANCE` สำหรับทดสอบ เพราะจะสร้างใบเสร็จสาธิตจริง ผล AI ต้องดูแยกจากการทดสอบที่ใช้ stub ใน unit tests ภาพ fixture เป็นภาพสร้างสำหรับทดสอบ ไม่ใช่ใบเสร็จจริงหรือหลักฐานความแม่นยำทั่วไป

`model_smoke.py` เรียก OCR และ Qwen จริง แล้วเทียบกับข้อมูลภาพสังเคราะห์ที่ทราบคำตอบ: exit 0 เมื่อข้อมูลตรงทุกช่องที่ตรวจ, exit 2 เมื่อเรียกโมเดลสำเร็จแต่ข้อมูลผิดบางช่อง ผล JSON อยู่ใน `test-results/model-smoke.json` อย่าแปล exit 2 ว่าติดตั้งโมเดลไม่ได้ และอย่าเรียกผลความแม่นยำนี้ว่าผ่าน

## กติกาข้อมูล

- เก็บเงินเป็นจำนวนเต็มสตางค์ ตรวจข้อมูลด้วย Decimal; ไม่คูณยอดรวมบรรทัดซ้ำด้วยจำนวนสินค้า
- ยอดสินค้ารวม + ส่วนลด/ค่าบริการ ต้องตรงยอดใบเสร็จ หากต่างต้องยืนยันส่วนต่างโดยชัดแจ้ง
- กราฟรวมส่วนลด/ค่าบริการและส่วนต่างแยกไว้ จึงเทียบกับรายจ่ายรวมได้
- เก็บข้อมูลใบเสร็จและสินค้าด้วย transaction เดียว ป้องกันกดยืนยันซ้ำ
- จำกัดภาพ JPG/PNG 10 MB และ 20 ล้านพิกเซล; หมุนภาพตาม EXIF และบันทึกภาพที่ normalize แล้ว
- รุ่นนี้ไม่มีระบบสมาชิก ใช้ใน LAN ที่ไว้ใจได้และไม่เปิดพอร์ตจากอินเทอร์เน็ต
- ยังไม่รองรับแก้/ลบรายการหลังยืนยัน, OCR ลายมือ, PDF, หลายหน้า, หลายผู้ใช้ หรือใบเสร็จยาวเกินขอบเขตโมเดล

## สำรองข้อมูล

หยุด `receipt-web` ก่อนสำรอง แล้วคัดลอกทั้ง `instance/` (รวม receipts.db และไฟล์ WAL/SHM ถ้ามี, uploads และ session.key) เปิดบริการอีกครั้งหลังคัดลอก เก็บข้อมูลส่วนนี้เป็นส่วนตัวและไม่ commit ลง Git
