## คำสั่งหลักที่ใช้

```bash
TESSDATA_PREFIX=/workspace/receipt-runtime/tessdata /workspace/receipt-tools/venv/bin/python -m pytest -q --junitxml=docs/evidence/pytest-results.xml
/workspace/receipt-tools/venv/bin/python scripts/browser_smoke.py --require-ai
```

ภาพหน้าจอใช้ใบเสร็จสังเคราะห์และรายการ “ร้านทดสอบ · ข้อมูลสาธิต” การรันทดสอบหลายครั้งสร้างหลายใบโดยตั้งใจ ไม่ใช่การกดยืนยันซ้ำที่บันทึกซ้ำ รายการทดสอบอยู่ใน instance แยกนอก checkout ไม่รวมในชุด source ที่ส่งให้ผู้ใช้

## ผล AI จริงที่ต้องอธิบาย

การทดสอบ direct inference หนึ่งครั้งใช้ OCR ประมาณ 0.41 วินาที และ AI 4.59 วินาทีบน cloud x86_64 (ไม่ใช่ Pi) โมเดลคืน JSON ได้ แต่เลือกข้อความ “SYNTHETIC TEST / NOT A REAL PURCHASE” เป็นชื่อร้าน, ให้ราคาขนมปัง 45.50 แทน 15.50 และจัดสินค้าเป็น “ของใช้” แทนอาหาร ผลรวมจึงไม่ตรงและหน้าเว็บแสดงคำเตือน ผู้ใช้แก้เป็นค่าที่ถูกต้องก่อนยืนยัน ผลนี้แสดงความจำเป็นของการตรวจแก้ ไม่ใช่หลักฐานว่า AI แม่นยำ

## เงื่อนไขก่อนส่งงานครบ

1. ทดสอบใบเสร็จจริงบน Pi 10 ใบ / 2 รูปแบบ รวมตัด WAN และรีบูต
2. ประเมินความถูกต้องและปรับ OCR/prompt โดยแยกชุดพัฒนากับชุดทดสอบ
3. เติมผลทดลองในรายงานและถ่ายคลิปจากระบบจริง

## ปัญหาที่พบและแก้ระหว่างพัฒนา

- ตัวอักษร Latin ในภาพสังเคราะห์แรกใช้ฟอนต์ไทยที่ไม่มี glyph ครบ: เปลี่ยน generator ให้ใช้ฟอนต์ Latin แยก แล้วตรวจ OCR ซ้ำผ่าน
- การทดสอบอ่านข้อความใน details ที่ปิดอยู่: อ่าน textContent เพื่อทดสอบเนื้อหาจริง
- JavaScript ของกราฟมีวงเล็บปิดขาด: แก้และตรวจ syntax/เบราว์เซอร์ซ้ำผ่าน

- การเรียก Qwen ครั้งแรกตอบซ้ำในช่องราคาจนเกิน token limit: เพิ่ม grammar สำหรับจำนวนเงิน/วันที่และตัวอย่าง JSON แล้วคืนผลได้ แต่ข้อผิดพลาดทางความหมายยังต้องตรวจโดยผู้ใช้
- เครือข่ายดาวน์โหลดโมเดลเคยปฏิเสธ 403: เพิ่มโดเมน Hugging Face/CDN ในค่าร่างและภายหลังดาวน์โหลดพร้อมตรวจ SHA256 ได้ โดยไม่ปิด TLS หรือข้าม checksum
